# API Reference

Interactive docs are also auto-generated by FastAPI at `/docs` (Swagger UI)
and `/redoc` once the server is running.

Base URL (local): `http://localhost:8000`

## `POST /events`

Submit one network/IoT flow record. Runs it through the detection engine
synchronously and creates an `Alert` if either the rules or the ML model
fire.

```bash
curl -X POST http://localhost:8000/events \
  -H "Content-Type: application/json" \
  -d '{
    "source_ip": "192.168.1.23",
    "destination_ip": "10.0.0.12",
    "protocol": "tcp",
    "destination_port": 22,
    "flag": "REJ",
    "src_bytes": 0,
    "dst_bytes": 0,
    "features": {"flag": "REJ", "src_bytes": 0, "dst_bytes": 0, "count": 12}
  }'
```

Returns `201` with the created event.

## `GET /events`

List ingested events. Query params: `limit` (default 50, max 500), `offset`,
`source_ip`.

## `GET /alerts`

List alerts, most-severe first. Query params: `limit`, `offset`, `severity`
(`LOW`/`MEDIUM`/`HIGH`/`CRITICAL`), `status` (`OPEN`/`ACKNOWLEDGED`/`CLOSED`),
`source_ip`.

```json
{
  "id": 1,
  "alert_code": "ALT-4A56249C",
  "event_id": 12,
  "source_ip": "192.168.1.23",
  "destination_ip": "10.0.0.12",
  "destination_port": 22,
  "protocol": "tcp",
  "detection": "Port scanning",
  "detection_source": "rule",
  "mitre_technique": "T1046",
  "mitre_technique_name": "Network Service Scanning",
  "confidence": 0.74,
  "risk_score": 74.0,
  "severity": "HIGH",
  "status": "OPEN"
}
```

## `GET /alerts/{id}`

Fetch a single alert. `404` if it doesn't exist.

## `PATCH /alerts/{id}?status=ACKNOWLEDGED`

Update an alert's status. `status` must be one of `OPEN`, `ACKNOWLEDGED`,
`CLOSED` (case-insensitive) or the request is rejected with `400`.

## `GET /devices`

List devices SentinelFlow has seen traffic from, ordered by risk score.
Query params: `limit`, `offset`, `min_risk_score`.

## `GET /devices/{ip_address}`

Fetch one device's aggregate stats (event count, alert count, highest risk
score observed). `404` if unseen.

## `GET /statistics`

Summary counts used by the dashboard: events analysed, alerts by severity,
suspicious device count, and top detection types.

## `GET /health`

Liveness check.
